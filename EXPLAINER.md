# Hidden Parity: A Plain-English Guide to Every Variable

This document walks through every variable, parameter, and metric in the codebase
and results — what each one is, what it does, and why parity-awareness makes the
difference.

---

## The Core Idea in One Sentence

Imagine someone is reading a book to you but randomly flips it upside-down without
telling you. You hear garbled words and think the speaker is just noisy — but
actually the signal is clean, and only the *orientation* is hidden. Parity is
that hidden orientation bit.

---

## The Signal Model

Every observation is generated by this formula:

```
y_t  =  s_t  ×  x_t  +  noise_t
```

| Symbol | Name | Plain English |
|--------|------|---------------|
| `y_t` | **observed signal** | What you actually measure at time step `t`. This is all you get. |
| `s_t` | **hidden parity / orientation** | A secret sign, always either **+1** or **−1**. You cannot see it directly. Think of it as "which way up is the book right now." |
| `x_t` | **carrier / template signal** | The clean underlying waveform — a sinusoid in the standard experiment, `amp × sin(θ_t)` in the Möbius experiment. This is what the signal *would* look like if parity never flipped. |
| `noise_t` | **observation noise** | Random Gaussian jitter with standard deviation `tau`. Represents sensor noise, measurement error, or any irreducible randomness. |

When `s_t = +1`, you see the carrier as-is.
When `s_t = −1`, the carrier is flipped — peaks become troughs and vice versa.
The noise is piled on top either way.

---

## Signal Generation Parameters

### `n` — Number of time steps
How long the experiment runs. We use **n = 20,000**. Longer series give the HMM
more evidence to work from, so estimates get sharper. Think of it as the number
of pages in the book.

### `tau` — Noise standard deviation
Set to **0.6** in the main experiment. Controls how loud the observation noise
is relative to the signal. Low tau → clean signal, easy to track parity. High
tau → noisy signal, harder. It is the "how much static is on the line" knob.

At `tau = 0.6` with `amp = 1.0`, the signal-to-noise ratio per step is `1/0.6 ≈ 1.67`.
That is moderately noisy — parity is detectable but not trivially obvious.

### `amp` — Signal amplitude
Set to **1.0**. This is the peak height of the carrier sinusoid `x_t`. The
relevant ratio is `amp / tau`: larger amplitude relative to noise makes parity
easier to see. We keep `amp = 1.0` and vary `tau` only.

### `seed` — Random seed
Set to **7**. Fixes the random number generator so results are exactly
reproducible. Change the seed and you get a different noise draw, but the same
statistical properties.

## Standard Experiment: The Flip-Rate Sweep

### `freq` — Sinusoid frequency of the carrier
Set to **0.007** cycles per step. The carrier is:
```
x_t = amp × sin(2π × freq × t)
```
At `freq = 0.007`, one full sine wave takes `1/0.007 ≈ 143` steps. This is
slow enough that the correlation structure is visible in the AR(1) fit, and fast
enough to complete ~140 full cycles over 20,000 steps. The frequency itself is
not being tested — it is just a carrier for the parity bit to ride on.

### `q` — Parity flip probability (the key variable)
At each time step, the hidden orientation `s_t` stays the same with probability
`1 − q`, or flips sign with probability `q`.

```
P(s_t ≠ s_{t-1}) = q
```

We sweep `q` across 8 values: **0.000, 0.001, 0.002, 0.005, 0.010, 0.020, 0.030, 0.050**

- `q = 0.000` → parity never changes. The signal is a noisy sinusoid, either
  always positive or always negative in orientation.
- `q = 0.050` → on average a flip every 20 steps. This is "frequent" relative to
  the 143-step wave period — the carrier gets reversed multiple times per cycle.

Everything in the standard experiment is about revealing what happens to naive
diagnostics as `q` increases, versus what the parity-aware model does.

## Möbius Experiment: Geometric Flips

### `omega` — Phase increment per step
Set to **0.03** radians/step. In the Möbius experiment the carrier is not a
fixed-frequency sinusoid but a phase that advances continuously:

```
θ_{t+1} = θ_t + omega   (plus optional noise)
x_t = amp × sin(θ_t)
```

At `omega = 0.03`, one full revolution (2π ≈ 6.28 radians) takes
`2π / 0.03 ≈ 209` steps. The circle is traversed ~95 times over 20,000 steps.

The parity flip here is *not* random. It is *geometric*: every time the phase
crosses the seam at θ = π (halfway around the circle), orientation flips. This
is the Möbius-strip analogy — walking all the way around brings you back
reversed.

### `seam` — The angle that triggers a flip
Hardcoded to **π** (180°). Think of it as a line drawn on the clock face. Every
time the moving hand crosses 6 o'clock, the book flips over.

### Why `freq ≠ omega`
They are parameters for two completely different things:
- `freq` is a *frequency* (cycles per step) in the standard experiment's signal space.
- `omega` is a *phase velocity* (radians per step) in the Möbius experiment's latent
  space. You cannot meaningfully set them equal — it would be like comparing
  kilometres/hour to revolutions/minute.

The effective flip rate from `omega = 0.03` is roughly
`omega / (2π) × 2 crossings per revolution ≈ 0.0095 flips/step`, which is
comparable to `q ≈ 0.005–0.01` in the standard sweep.

## The Three Diagnostic Tools ("Blind" to Parity)

These tools see only `y_t`. They cannot look inside and track `s_t`.

### AR(1) — Autoregressive fit

**What it does:** Fits the simplest possible time-series model:
```
y_t = a × y_{t-1} + error_t
```
Finds the single number `a` (the lag-1 autocorrelation coefficient) that best
predicts the next value from the current one.

**Parameters returned:**
- `AR1_a_hat` — the fitted coefficient `a`. At `tau = 0.6` with no flips it
  comes out around 0.57–0.59, reflecting the true autocorrelation structure of a
  noise-corrupted sinusoid.
- `AR1_resid_std` — standard deviation of the prediction errors
  `error_t = y_t − a × y_{t-1}`. This is the model's "unexplained noise" — how
  wrong it is on average.

**What parity flips do to it:** When the hidden sign flips, the carrier suddenly
reverses direction. The AR(1) model, which assumed a smooth trend, sees this as a
large unexpected jump and attributes it to noise. So `AR1_resid_std` *rises* as
`q` increases:

```
q = 0.000 → resid_std = 0.751
q = 0.050 → resid_std = 0.792
```

The model gets worse, but it cannot tell you *why*. It just says "noisier."

**Test:** `test_ar1_fit_known_coefficient` — verifies that on a clean AR(1) signal
with known `a_true = 0.7`, the fitted `a_hat` is within 0.02 of truth.

---

### FFT peak/total — Spectral concentration

**What it does:** Converts the signal to the frequency domain (a list of how
much energy is at each frequency). Then measures how *concentrated* the energy is:

```
FFT_peak_over_total = (height of the tallest frequency spike) / (total energy across all frequencies)
```

A pure sine wave at one frequency has a value near **1.0** — all energy at one
spike. White noise has a value near **0** — energy spread everywhere.

**What parity flips do to it:** Each flip effectively inverts the carrier.
Half the time it looks like a +1 × sin, half the time like −1 × sin. Those two
average out to zero in the frequency domain — spectral energy smears across all
frequencies. So `FFT_peak_over_total` *falls* as `q` increases:

```
q = 0.000 → peak/total = 0.0132
q = 0.050 → peak/total = 0.0011
```

Again: the tool sees degradation but cannot diagnose the cause as "hidden flips."

**Tests:**
- `test_fft_pure_sinusoid_high_concentration` — a perfect sinusoid gives > 0.5 concentration.
- `test_fft_white_noise_low_concentration` — pure noise gives < 0.05.

## The Parity-Aware Model: HMM

The **Hidden Markov Model (HMM)** explicitly represents the thing the other
tools ignore: the hidden orientation `s_t`.

It models the world correctly:
- There is a hidden bit (`s_t`) that is either +1 or −1.
- That bit flips with probability `q` at each step.
- Given `s_t`, the observation `y_t` is `s_t × x_t + Gaussian noise`.

Because the model knows the structure of what is being hidden, it can
*unscramble* it. It sweeps through the entire 20,000-step sequence twice
(forward and backward in time) to accumulate evidence about `s_t` at every
step — then updates its estimates of `q` and `tau`. This process (called EM,
Expectation-Maximisation) is repeated up to 25 times until it converges.

### Parameters and outputs

| Variable | Plain English |
|----------|---------------|
| `q_init` | Starting guess for the flip rate before EM begins. Set to `max(q_true, 0.005)` to give the algorithm a sensible starting point. |
| `n_iter` | Maximum number of EM iterations (25). Each iteration improves the estimate. Stops early if the improvement falls below `tol = 1e-6`. |
| `HMM_q_hat` | The HMM's final estimate of the flip rate. Compared directly to `true_q`. |
| `HMM_tau_hat` | The HMM's estimate of the noise level `tau`. Because it correctly accounts for orientation uncertainty, it does *not* inflate this — it stays near 0.60 across the full sweep. |
| `Parity_acc` | What fraction of the 20,000 hidden orientation values `s_t` the HMM got right. |
| `log_evidence` | How probable the observed data is under the fitted model (in log scale). More negative = data is harder to explain. |

### Why `HMM_tau_hat` staying flat matters
The AR(1) model, seeing unexplained jumps, silently absorbs them into its noise
estimate. The HMM does not — it says "those jumps are not noise, they are parity
flips, and the flip rate is q̂." As a result, its noise estimate stays accurate
even as `q` rises. This is the core practical payoff: you get a *correct*
decomposition of variance rather than a lumped "everything is noise" answer.

### `parity_accuracy` — why it checks both signs
The HMM cannot know whether the very first `s_0` was +1 or −1 — both are equally
probable a priori. It can only recover *changes* in orientation, not the absolute
starting value. So accuracy is computed as:

```
max(fraction matching s_true,  fraction matching −s_true)
```

If the HMM got the whole sequence perfectly but started with the wrong global
sign, this still scores 1.0 — correctly.

**Tests:**
- `test_parity_accuracy_perfect_flipped` — confirms that a perfectly-recovered
  but globally-sign-flipped sequence scores 1.0.
- `test_hmm_recovers_q` (5 seeds) — HMM must get q̂ within 0.007 of truth and
  parity above 92% at q=0.02, n=10,000.
- `test_hmm_q0_no_flips` — at q=0, HMM should output q̂ < 0.01 and accuracy > 99%.

## Mutual Information and the `1/(2 ln 2)` Constant

### What mutual information (MI) measures here
"How many bits of information does one observation `y_t` carry about the
hidden parity bit `s_t`?" If MI = 0, observing `y_t` tells you nothing about
whether `s_t` is +1 or −1. If MI = 1 bit, observing `y_t` perfectly resolves it.

### The small-signal approximation
When the signal is weak relative to noise (`amp/tau` small), the MI simplifies to:

```
I(s_t ; y_t)  ≈  a² / (2 τ² ln 2)   bits
```

Where `a = amp` and `τ = tau`. The number `1/(2 ln 2) ≈ 0.7213` is the
**curvature constant** — it tells you how fast parity information accumulates
as you increase signal strength.

**What this means practically:** To double the information per observation you
need to *quadruple* the signal amplitude (because MI scales as `a²`). This is
why parity is so hard to detect from a single observation — but with 20,000
observations the HMM integrates all of them.

### `estimate_mi_parity_bits` — Monte Carlo verification
Generates 500,000 (s, y) pairs and empirically estimates the MI. This confirms
the formula is not just algebra — it matches real simulated data within 8%.

**Tests:**
- `test_mi_small_snr_matches_curvature` — Monte Carlo MI within 8% of formula at a=0.1, tau=1.0.
- `test_mi_approx_scales_quadratically` — doubling `a` quadruples MI (ratio = 4.0 exactly).

## Möbius Generator in Detail

### `theta` — The continuous phase
A number that increases by `omega` each step:
```
θ_t = θ_0 + t × omega   (plus optional jitter)
```
It is not bounded — it just keeps growing. But its *remainder mod 2π* is a
position on the circle (0 to 360°).

### How flips are counted exactly
At each step the code computes how many times the path from `θ_{t-1}` to `θ_t`
crossed the seam at `π` (or any multiple of 2π away from it). Each crossing
flips `s_t` once. The counting is exact — if two crossings happen in one step,
they cancel back to no net flip. This handles any speed of rotation correctly.

### `noise_theta` — Phase jitter
Defaults to **0.0** in the main experiment (deterministic phase march). If set
nonzero, the phase walk becomes stochastic — you could model a noisy clock or
an oscillator with frequency drift.

**Tests:**
- `test_mobius_flip_count_matches_seam_crossings` — with zero noise, the number
  of flips equals the analytically computed number of seam crossings exactly.
- `test_mobius_hmm_recovers_parity` (3 seeds) — HMM achieves > 90% accuracy
  even though it models flips as random rather than geometric.

## Reading the Results Table

```
true_q | AR1_resid_std | FFT_peak/total | HMM_q_hat | HMM_tau_hat | Parity_acc
```

**A summary of what each column tells you:**

| Column | Good value | What degradation means |
|--------|-----------|------------------------|
| `true_q` | — | The ground truth you set. |
| `AR1_resid_std` | Low (near tau=0.6) | Rising → AR(1) is absorbing flip-induced variance as noise. Cannot diagnose why. |
| `FFT_peak/total` | High (concentrated) | Falling → spectral energy smears as parity cancels the carrier. Cannot diagnose why. |
| `HMM_q_hat` | Close to `true_q` | Large error → HMM is struggling (only happens at very high noise or very rare flips). |
| `HMM_tau_hat` | Stays near 0.60 | Rising would mean the HMM is also confusing flips with noise — it doesn't. |
| `Parity_acc` | Near 1.0 | Falling → hidden orientation harder to track. Still > 94% at q=0.05. |

The punchline: the first two columns get worse as `q` increases but give you no
information about `q`. The last three columns track `q` precisely and tell you
exactly how much of the variance is "noise" versus "hidden orientation changes."

## Summary: Why Parity Beats Blind Models

| Question | AR(1) / FFT answer | HMM answer |
|----------|--------------------|------------|
| Is there a hidden orientation? | Cannot tell | Yes, and its flip rate is q̂ |
| How much is signal vs noise? | Conflates both into one noise number | Separates them: tau stays stable |
| Where did the flips happen? | No information | s_hat: step-by-step reconstruction |
| Does it work for geometric flips (Möbius)? | Still blind | Yes — 98.15% accuracy |
| Why? | Only looks at local consecutive differences | Integrates evidence across the *entire* sequence, forward and backward in time |

The value of the parity framework is not that the math is complicated — it is
that it asks the right question. Once you write down "there is a hidden ±1 that
flips with rate q," a standard HMM solves for it cleanly. The hard part was
knowing to look for it.
